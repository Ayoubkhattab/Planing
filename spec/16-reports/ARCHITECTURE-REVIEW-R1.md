# ATAM-lite — Release 1

## 1. Utility tree (أعلى أولوية فقط)
| الجودة | السيناريو | الأولوية | أين يتحقق |
|---|---|---|---|
| Security | عدم الاستدلال: البيانات المخفية لا تغير أي مخرج (بحث، رسم، مواقف، بلاطات، تنبيهات) | H / H | P-51..P-53، P-64، QAS-SEC-002/011/012 |
| Security | سحب الصلاحية يسري من الطلب التالي في كل المسارات | H / H | PL-SECURITY-CONTEXT §2، LabelCheck (CR-47) |
| Correctness | "ماذا كنا نعرف في لحظة X" قابل للإجابة لكل قرار وتقييم وهوية | H / H | LIB-CLAIMS-KERNEL، SPEC-PLAN §1، ER-MODEL |

## 2. نقاط الحساسية العابرة للنظام
| النقطة | تؤثر على | معالجة |
|---|---|---|
| PDP ومخزن الإصدارات الأمنية في المسار الحرج | التوفر، الأداء، الأمن | مقيّم مضمّن، Valkey مكرر، fail-closed مقبول (RSK-018) |
| مكتبة الادعاءات والزمن | الصحة، الأداء | مكتبة واحدة، oracle 500 حالة، جدول current (RSK-019/020) |
| KMS / مخزن المفاتيح | كل البيانات | HSM مكرر، سجل إتلاف، بوابة استعادة (RSK-025) |
| Kafka | الإسقاطات، المقيّمون، المزامنة | RF=3، MirrorMaker، outbox يحمي الأوامر من تعطله |

## 3. المفاضلات المقبولة على مستوى النظام
1. **fail-closed في الأمن** مقابل التوفر.
2. **الرؤية أولاً** تجعل النتائج مختلفة لكل مستخدم، فتقل فعالية الذاكرات المشتركة.
3. **ثنائية الزمن** تضاعف حجم بيانات T1 مقابل المساءلة التاريخية.
4. **بصمة تشغيلية كبيرة** (8 خدمات ذات حالة لكل خلية) مقابل تحقيق الأحمال والقدرات المطلوبة (RSK-026).
5. **لا ذكاء اصطناعي في R1** مقابل تثبيت النواة والأمن أولاً.

## 4. محاور المخاطر (Risk themes)
| المحور | المخاطر | الحالة |
|---|---|---|
| القدرة التشغيلية | RSK-005، RSK-026 | يحتاج تأكيد حجم الفريق (UNK-012) |
| القيم الخارجية غير المعروفة | UNK-002، UNK-012 | لا تحجب التصميم؛ تحجب G8 |
| الأداء غير المقاس | كل QAS-PERF | يُغلق بالاختبار في Pilot |
| جودة البيانات الخارجية ومطابقة الأسماء | RSK-006، RSK-021 | بوابة تقييم + عينات Pilot |

## 5. غير مخاطر (Non-risks)
- حدود السياقات صمدت عبر 10 شرائح دون تعديل؛ الملكية أحادية لكل كائن.
- كل تقنية مرتبطة بدليل ولها مُحفّز مراجعة.
- كل متطلب وسيناريو جودة متتبع إلى تحقق.
