## 2. ضبط التغيير بعد خط الأساس
| نوع التغيير | الإجراء |
|---|---|
| تصحيح لا يغير سلوكاً (صياغة) | تعديل مباشر + سجل تغيير في الملف |
| تغيير سلوك داخل Aggregate (حالة، شرط، ثابت) | تحديث بيانات مصدر الشريحة → إعادة توليد (Aggregates، عقود، قبول) → فحص (w9_check + lint) → مراجعة → اعتماد |
| تغيير عقد عام | إصدار رئيسي جديد مع تعايش ≥ 6 أشهر (QAS-EVO-001) |
| تغيير قرار معماري | ADR جديد يلغي أو يعدّل، مع أثره على الشرائح |
| تغيير تقني عند مُحفّز مراجعة | ADR + قياس يثبت المحفز |

**قاعدة ذهبية:** لا تعديل يدوي على الملفات المولّدة: Aggregates، كتالوجات الأوامر والاستعلامات والأحداث، كل ملفات OpenAPI وAsyncAPI والأخطاء، وملفات القبول `*-state-machine.md` (القائمة في `13-verification/tooling/spec-tooling.md`). التعديل في بيانات المصدر ثم إعادة التوليد — وإلا ضاع التعديل في التوليد التالي (درس CR-50، CR-55).
