# دراسة تحليل وتصميم النظام (System Analysis and Design)

## 0. ما هذه الدراسة

`spec/` يحدد **ماذا** يفعل النظام (سياقات، Aggregates، أوامر، أحداث، عقود، سياسات)، و`spec/17-system-study/` يفهرسه ويتحقق من اتساقه. هذه الدراسة تحدد **كيف يُبنى**، على الورق وقبل أي كود: تحليل النظام بمخططات هندسة البرمجيات، ثم التصميم بمعمارية Hexagonal داخل كل وحدة نشر، ثم الجاهزية للتنفيذ.

**لا كود في هذه الدراسة.** المخططات بصيغة Mermaid (نص قابل للمراجعة في Git، يعرضه GitHub مباشرة). القرارات المصادَق عليها (ADR-P01..P16، TD-01..TD-19، وحدات النشر، الخلايا) مدخلات ثابتة لا تُعاد مناقشتها؛ ما يُضاف موثّق بقرار جديد (ADR-P17، ADR-P18).

## 3. تصنيف العمليات (أساس قصص المستخدم)

كل عملية في النظام تُصنَّف في نوع واحد، ولكل نوع قالب قصة وأسئلة قبول خاصة به (التفصيل في `05-user-stories/00-guide.md`، المرحلة 2):

| النوع | المصدر في المواصفات | ما يميّزه |
|---|---|---|
| إنشاء | أوامر تنشئ Aggregate (∅ → حالة) | المدخلات الإلزامية، التحقق، الإصدار 1، عدم التكرار |
| تعديل | أوامر لا تغيّر الحالة | التزامن (If-Match)، النسخ، ما يُجمَّد بعد حالة |
| سير عمل | أوامر تنقل الحالة | فصل المهام، الحالة السابقة، الإشعار |
| حذف / إنهاء | الانتقال إلى حالة نهائية، المحو، الإتلاف | لا حذف فعلي؛ الإيقاف أو الإتلاف بالمفتاح؛ التجميد القانوني؛ السبب |
| جلب / استعلام | `QRY-*` | `allowed_scope`، الإفصاح الصفري، الترقيم بمؤشر، as-of |
| تحليل | BC03، مطابقة الكيانات، التعارض، طلب AI | الأدلة والنسب، الثقة، مستوى الاستقلالية |
| تقارير ومنتجات | BC06، التصدير، الأرشيف، التدقيق | التصنيف، العلامة المائية، اعتماد بغير المؤلف |
| عمليات النظام | انتقالات `SYS:` (175) والمستهلكون | المحفِّز، إعادة المحاولة، عدم التكرار |
| تكامل | الاستيراد، المحوّلات، المزامنة | المصدر والموثوقية، العزل، التعارض |

## 4. طريقة العمل

كل مرحلة تمر بنفس الدورة: **استكشاف ← تخطيط ← تنفيذ ← تحقق ← تصحيح ← دمج**.

| الخطوة | ماذا يحدث | من |
|---|---|---|
| استكشاف | قراءة المصادر المعنية وجمع الحقائق قبل الكتابة | المصمم، ووكيل Explore للبحث الواسع |
| تخطيط | تحديد الملفات والأقسام وما يُولَّد وما يُكتب | المصمم |
| تنفيذ | الكتابة؛ والمحتوى الضخم المشتق يُولَّد بسكربت | المصمم؛ وكلاء متوازون لملفات منفصلة |
| تحقق | فحص آلي (`verify_study.py` بعد توسيعه) + مراجعة مستقلة | سكربت + وكيل مراجعة لم يكتب الملف |
| تصحيح | إصلاح كل ما وُجد، وتسجيل ما يمس المصادر كـCR | المصمم |
| دمج | PR لكل مرحلة | مالك المشروع يدمج |

**المراحل:** (1) الأساس المعماري ← (2) المولّدات والمحتوى الضخم: القصص، الواجهات، قاعدة البيانات، الحالات، القواعد، الأحداث ← (3) بقية التحليل ← (4) بقية التصميم ← (5) الجاهزية للتنفيذ.
