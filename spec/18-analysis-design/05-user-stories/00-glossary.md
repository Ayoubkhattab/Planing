## 1. الغرض

مرجع واحد للغة القصص:

1. **المصطلحات** التي تتكرر في القصص، بمعناها البسيط.
2. **الأدوار** التي تظهر في «كـ…»، بأسمائها العربية الموحدة.
3. **رسالة المستخدم** لكل رمز خطأ في كتالوج الأخطاء، وهي النص الذي يراه المستخدم وتنقله سيناريوهات الرفض حرفيًا.

المسرد الملزم في `00-governance/glossary.md` هو المرجع للمصطلحات العامة. وهذا الملف لا يكرره، بل يضيف ما تحتاجه القصص.

## 2. المصطلحات

| المصطلح | المعنى في القصص |
|---|---|
| السياق المشترك للميزة | الشروط التي تبدأ منها كل قصص الميزة: مستأجر نشط، وحزمة السياسات الأساسية، ومستخدم مسجّل الدخول ومخوَّل |
| الرفض المشترك | حالات الرفض التي تنطبق على كل أوامر الميزة، وتُكتب مرة واحدة في القسم 2 من ملف الميزة |
| عدم الإفصاح | من لا يحق له رؤية شيء يتلقى ردًا بشكل «غير متاح» تمامًا، فلا يعرف أنه موجود |
| مفتاح منع التكرار | معرّف يرسله العميل مع كل أمر، فإعادة الطلب نفسه لا تُنفَّذ مرتين |
| حماية التعديل المتزامن | يُرسل كل أمر بإصدار البيانات الذي يراه المستخدم، فإن عدّلها غيره في الأثناء يُرفض الأمر |
| الحدث | سجل لشيء وقع، مثل «بدأت المهمة». تستقبله أجزاء أخرى من النظام لتتصرف بناءً عليه |
| سجل التدقيق | سجل لا يُعدَّل لكل عملية: من فعلها، ومتى، وعلى ماذا، وبأي نتيجة |
| المستأجر | الجهة المستقلة التي تستخدم المنصة، وبياناتها معزولة عن غيرها |
| التصنيف الأمني | مستوى سرية البيانات. ولا يرى المستخدم إلا ما يسمح به تصريحه |
| التصريح الأمني | المستوى الذي يُسمح للشخص برؤيته من البيانات المصنفة |
| العمل دون اتصال | تنفيذ أوامر محددة على الجهاز الميداني دون شبكة حتى 72 ساعة، ثم مزامنتها |
| المزامنة | رفع ما سُجّل على الجهاز إلى الخادم، وتنزيل ما تغيّر عليه |
| تعارض المزامنة | أمر وصل من الجهاز مبنيًا على حالة قديمة، فلا يُطبَّق ولا يُرفض بصمت، بل يحسمه إنسان |
| التعليق | علامة يضعها المسؤول على عنصر في أي حالة غير نهائية، فيُرفض كل تغيير عليه عدا الإلغاء ورفع التعليق |
| فصل المهام | لا يجوز أن يعتمد الشخص نفسه ما قدّمه أو طلبه |
| الحالة النهائية | حالة لا يُقبل بعدها أي تغيير، مثل «مغلقة» و«ملغاة» |
| مستنتج **[Derived]** | ما لا يذكره المصدر صراحة واستنتجته الدراسة، ويحتاج تأكيد المالك |

## 3. الأدوار

### 3.1 أدوار الأعمال

| الدور | بالإنجليزية | من هو |
|---|---|---|
| القيادي التنفيذي | Executive | القيادة العليا: يمنح السلطات ويعتمد ما يخصها |
| المدير | Manager | القيادة: يتابع ويتدخل ويعتمد |
| المخطِّط | Planner | يعدّ الخطط وينشئ المهام ويسندها |

| المستخدم الميداني | Field User | ينفّذ المهام ويجمع المعلومات في الميدان |
| مدير الموارد | Resource Manager | يدير الأصول والمجمعات والتخصيص |
| مستخدم الإمداد | Logistics User | يدير طلبات الإمداد والشحنات |
| مدير المخاطر | Risk Manager | يسجّل المخاطر ويتابع معالجتها |
| مدير التدريب | Training Manager | يدير سيناريوهات التدريب والتمارين |
| مدير المعرفة | Knowledge Manager | يراجع المعرفة والدروس المستفادة وينشرها |
| أمين الأرشيف | Archivist | يحفظ السجلات ويسترجعها |
| مسؤول الأمن | Security Officer | يدير التصنيف والتصاريح والاستثناءات الأمنية |
| المدقِّق | Auditor | يطّلع على سجل التدقيق ويتحقق من سلامته |
| مسؤول الإدارة | Administrator | يدير المستخدمين والأدوار والإعدادات في المستأجر |

### 3.2 أدوار المنصة والسلطة

| الدور | بالإنجليزية | من هو |
|---|---|---|
| مشغّل المنصة | Platform Operator | يدير المستأجرين والخلايا وتشغيل المنصة |
| مهندس الذكاء الاصطناعي وحوكمته | AI platform engineer / AI governance | يعتمد النماذج والتوجيه والأدوات |
| مهندس التكامل | Integration engineer | يدير الاتصالات والمحوّلات |
| السلطة القانونية والامتثال | Legal/Compliance authority | تعتمد الاحتفاظ والتجميد القانوني والمحو |
| صاحب السلطة أو المعتمِد الثاني | Authority holder / second approver | يملك منح سلطة، أو يعتمد ما أعدّه غيره |

### 3.3 أدوار العلاقة بالعنصر

يحددها العنصر نفسه لا الدور الوظيفي:

| الدور | من هو |
|---|---|
| المسندة إليه والمراجع | من أُسندت إليه المهمة، ومن يراجع نتيجتها |
| المالك والطالب والمشارك | من يملك العنصر أو طلبه أو يشارك فيه |
| المستلم والمشترك | من وصله الإشعار أو التنبيه، أو اشترك في متابعة عنصر |
| أدوار الحادثة | المبلِّغ، ومقيّم الحادثة، وقائدها |
| أدوار الخطر | محدِّد الخطر، والمقيّم، وموافق المعالجة، ومالك النطاق |
| الشخص الثاني | محلل أو مسؤول ثانٍ، لفصل المهام |
| أي مستخدم مخوَّل | أي مستخدم ضمن نطاقه ومصرَّح له بتصنيف العنصر |

### 3.4 النظام

«كـ النظام» في قصص النوع «نظام»، وتشمل: المجدول، وخدمات المحوّلات والاستيراد، وهويات الخدمات الداخلية.

## 4. رسائل المستخدم

### 4.1 قواعد الرسالة

- تقول ما حدث بلغة المستخدم، وما يفعله إن كان هناك ما يفعله.
- بلا رموز ولا مصطلحات تقنية.
- لا تكشف ما لا يحق للمستخدم معرفته: الرفض بسبب الصلاحية على مورد غير مرئي يظهر «غير متاح».
- السيناريو ينقل الرسالة حرفيًا. وتغيير الرسالة يكون هنا فقط.
- الرسالة الإنجليزية تُضاف عند بناء ملفات الترجمة، بالمفتاح نفسه (رمز الخطأ).


### 4.2 طلب غير صالح

| الرمز | HTTP | الرسالة |
|---|---|---|
| `PAYLOAD_TOO_LARGE` | 413 | حجم الطلب أكبر من المسموح. قلّل حجم البيانات أو قسّمها |
| `UNSUPPORTED_MEDIA_TYPE` | 415 | نوع المحتوى المرسل غير مدعوم |
| `VALIDATION_FAILED` | 400 | بعض البيانات ناقصة أو غير صحيحة. راجع الحقول المعلَّمة |

### 4.3 المصادقة والصلاحية وعدم الإفصاح

| الرمز | HTTP | الرسالة |
|---|---|---|
| `APPROVAL_REQUIRED` | 403 | هذا الإجراء يحتاج موافقة. أُرسل الطلب إلى صاحب الصلاحية |
| `AUTHZ_DENIED` | 403→404 | لا تملك صلاحية هذا الإجراء |
| `MFA_STEP_UP_REQUIRED` | 401 | هذا الإجراء يحتاج تأكيد هويتك مرة أخرى |
| `NOT_FOUND` | 404 | غير متاح |
| `PERMISSION_DENIED` | 403→404 | لا تملك صلاحية منح هذه السلطة في هذا النطاق |
| `SEGREGATION_OF_DUTIES` | 422 | لا يجوز أن يعتمد الشخص نفسه ما قدّمه أو طلبه |
| `UNAUTHENTICATED` | 401 | انتهت جلستك. سجّل الدخول مرة أخرى |

### 4.4 التعديل المتزامن ومنع التكرار

| الرمز | HTTP | الرسالة |
|---|---|---|
| `IDEMPOTENCY_KEY_REUSED` | 422 | طلب مكرر بمحتوى مختلف |
| `VERSION_CONFLICT` | 409 | تغيّرت البيانات منذ فتحتها. راجع التغييرات ثم أعد المحاولة |

### 4.7 المنصة والخدمات المساندة

| الرمز | HTTP | الرسالة |

### 4.8 أسباب الرفض غير المتزامن

ليست رموز أخطاء، بل أسباب تُحفظ مع حالة «مرفوض» في طلب تخصيص أو تأهيل، ويراها المستخدم سببًا للرفض:

| السبب | الرسالة |
|---|---|
| `CERTIFICATION_EXPIRED` | انتهت صلاحية الشهادة المطلوبة |
| `GEOGRAPHY_MISMATCH` | الموقع خارج النطاق الجغرافي المطلوب |
| `POLICY_DENIED` | رفضته سياسة الجهة |
| `POOL_NOT_ACTIVE` | مجمع الموارد غير نشط |
| `REQUIRES_CERTIFICATION` | يتطلب شهادة غير متوفرة |
| `RESOURCE_TYPE_MISMATCH` | نوع المورد لا يطابق المطلوب |
| `WINDOW_OUTSIDE_TARGET` | الفترة المطلوبة خارج الفترة المستهدفة |

> **ملاحظة:** ثلاثة رموز تذكرها المتطلبات ولا يذكرها كتالوج الأخطاء (`CLASSIFICATION_REQUIRED`، `GEOMETRY_INVALID`، `SOURCE_REQUIRED`). لا رسائل لها هنا حتى يُحسم أمرها في المصدر (S-27 في `18-error-handling.md` §8).
